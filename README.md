# Papagun

Локальный проект на Python: Excel → проверка и подготовка данных → самостоятельная генерация PPTX. Будущее приложение запускается через Windows EXE; GUI пока не реализован.

## Текущий запуск

Весь рабочий код, генерация и проверки находятся в [excel_loading.ipynb](excel_loading.ipynb). Откройте notebook из корня проекта и выполните ячейки сверху вниз. После обновления notebook перезапустите ядро, чтобы удалить прежние определения функций.

Нужны pandas, openpyxl и python-pptx 1.0.2. Проверка зависимостей находится в начале; необязательная установка выключена по умолчанию. Локальное окружение: Python 3.13.5 / pandas 3.0.3 / openpyxl 3.1.5 / python-pptx 1.0.2. Полное окружение пока не закреплено.

## Входы и результаты

Читаются две книги NL из «Исходники» и Excel-справочник названий центров. Формируются отдельные quantity_df и financial_df по семь колонок: первой идёт «Код статей», затем прежние шесть полей. В таблицах только январь–декабрь; происхождение и диагностика хранятся отдельно.

Входная презентация и ранее созданные PPTX не нужны. Презентация NL за 9 месяцев использовалась при разработке только как визуальный пример. Списки центров, размеры, цвета, подписи и диаграммы теперь заданы в коде. Логотип хранится отдельно в resources/nephrolife_logo.jpg; при его отсутствии числовой отчёт всё равно создаётся.

Генерация создаёт папку output при отсутствии и сохраняет два файла:

- NL_пациенты_2026_слайд2.pptx — 18 слайдов: прежние 15 и три новых по кодам статей 211.11 и 211.12;
- NL_test_branch_counts_fixed.pptx — 90 тестовых слайдов, по пять наборов каждого показателя.

Существующие результаты обновляются под теми же именами после проверки обоих новых пакетов. Они не участвуют в расчётах и оформлении; необязательные резервные байты используются только для отката при ошибке записи. Повторный запуск не добавляет дубликаты. Исходные Excel и PPTX не изменяются. Постоянные промежуточные презентации не создаются.

## Показатели

- Пациенты: сентябрь, строка Excel 14, 18 согласованных центров; план «Утверждено», факт «Факт по 1С».
- Процедуры: сумма января–сентября строки 15, 19 центров; готовые сводные периоды Excel не используются.
- Нагрузка: сентябрьские пациенты / аппараты из строк 14/13, 18 центров; общие нагрузки — отношения сумм.
- Новые слайды 7–9: количественный, финансовый и квартальный расчёты по статьям «Эритропоэтин короткого действия» и «Сахарат железа (Венофер)(Аджифер)», строки Excel 49/50; правила совпадают с прежними слайдами препаратов. Для двух августовских количественных и 38 сентябрьских финансовых пропусков факта 1С согласованы точечные нули в модели.
- Слайды 10–12: те же три расчёта для «Севеламера карбонат» и «Кальция ацетат (кальций ацтек)», строки Excel 54/55. Для них применяются те же точечные правила нуля в модели.
- Слайды 13–15: те же расчёты для кодов 211.07 и 211.10, строки 53/56. Начиная со слайда 4, данные выбираются по «Код статей»; на слайдах показывается «Наименование статей» соответствующей книги. Поэтому количественные слайды показывают Паракальцитол 5 мкг, финансовый — 10 мкг, как записано в источниках.
- Слайды 16–18: количественный, финансовый и квартальный расчёты для кодов 211.11/211.12, строки 57/58. Код 211.11 подписан как Кальдерол 1 мкг/мл в количественной книге и 2 мкг/мл в финансовой; каждый слайд показывает название своей книги.
- Препараты: две точные статьи Дарбэпоэтина альфа (Аранесп), 30 и 20 мкг, сумма января–сентября, 19 центров. Только два пропуска августовского факта «Атырау Нурсая» считаются нулями по разрешению пользователя. Подписи значений — целые числа. Названия статей расположены по центру внутри рамок диаграмм; отклонение = «Факт по норме» − «Факт по 1С». Отрицательные столбцы и метки красные; положительные столбцы серые, метки зелёные. Расчёты сохраняют исходную точность.

Редактируемые диаграммы и встроенные XLSX создаются программно. Формулы, периоды и состав центров остаются правилами конкретных согласованных прототипов; новые бизнес-фильтры не вводятся.

Финансовые препараты: те же две статьи из financial_df, январь–сентябрь; ряды «Факт по норме», «Факт по 1С», «отк:» (норма минус факт). Суммы переводятся из тенге в тыс. тенге, подписи целые, вычисления не округляются. По отдельному согласованию отсутствующий сентябрьский факт этих статей у 19 центров равен нулю только в модели слайда. См. docs/SLIDE6.md.

Квартальные препараты: quantity_df, те же статьи и 19 центров; суммы нормы, факта 1С и их разности за 1/2/3 кварталы и 9 месяцев. Месяцы суммируются в модели без чтения готовых квартальных блоков Excel. См. docs/SLIDE7.md.

## Проверки и настройки

REPORT_MONTH, BRANCH_COUNTS, PROCEDURE_BRANCH_COUNTS, LOAD_BRANCH_COUNTS, FINANCIAL_BRANCH_COUNTS, QUARTER_BRANCH_COUNTS, GENERATE_PRESENTATIONS, RUN_CHECKS, RENDER_PREVIEWS задаются в начале notebook. По умолчанию генерация и проверки включены, просмотр выключен.

Проверяются исходные значения, ошибки, нулевые знаменатели, все серии/итоги/встроенные XLSX, геометрия и целостность ZIP. Холодный запуск проверяется в новой пустой папке с запретом чтения входных PPTX и повторного импорта бюджетов. Проверяются повторный запуск и откат при ошибке сохранения второго файла.

PowerPoint нужен только для необязательной проверки и просмотра уже готовых результатов; генерация от него не зависит. Превью и диагностический JSON временные. Сохранённые outputs notebook должны оставаться пустыми.
