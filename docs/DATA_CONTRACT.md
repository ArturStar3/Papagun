Все функции импорта, формирования таблиц, модели пациентов, экспорта и проверок находятся непосредственно в `excel_loading.ipynb`. Перенос из прототипных модулей не изменил правила данных, формулы, округление или сортировку. Отдельные модули появятся позже при реализации GUI.

## Единая таблица филиалов в notebook
Подтверждено пользователем: использовать количественный бюджет и сформировать единый DataFrame всех филиалов с колонками «Наименование филиала», «Наименование статей», «Месяц», «Утверждено», «Факт по норме», «Факт по 1С».

С 2026-10-22 по поручению пользователя источники — Исходники/NL_Кол. Бюджет.xlsx и Исходники/NL_Фин. Бюджет.xlsx. Обе таблицы формируются за один запуск: quantity_df и financial_df, переключение SOURCE_BOOK не требуется. В обеих книгах проверены прежние 20 листов филиалов; список явно указан в BRANCH_SHEETS. Сводные, вспомогательные листы и АУП не включены.
Фактическая структура: C6 — «Наименование статей»; строка 6 содержит месяцы, строка 7 — «Утвержд.», «Факт по норме», «Факт по 1С», «Отклонение». Месячные блоки начинаются в I, M, Q, U, Y, AC, AG, AK, AO, AS, AW, BA. Из каждого блока используются первые три колонки, отклонение не включается. Кварталы, полугодия и годовые итоги по колонкам исключены.

Основная таблица количественной книги: строки 9–141 включительно. Вспомогательные пояснения и алгоритмы ниже строки 141 исключены. Для финансовой книги используется диапазон 9–193; книги не объединяются между собой.
Названия статей копируются из C, филиал — из имени листа, месяц — русское название из заголовка, без изменения регистра названий статей и округления значений. Строки с пустым названием статьи пропускаются; именованные итоговые строки, строки без кода и повторяющиеся названия сохраняются. Скрытые строки отдельно не исключаются.
Гранулярность: одна строка исходной статьи × один филиал × один месяц. Все 12 месяцев сохраняются, даже если показатели пусты. Филиал + название статьи + месяц не обязательно уникальны: исходные названия повторяются. Не удалять дубликаты и не суммировать итоговые строки вместе с детализацией без согласованного правила.

quantity_df и financial_df содержат по шесть запрошенных колонок. branches_df оставлен как ссылка на quantity_df. Пустые показатели представлены pd.NA, нули сохраняются. Тип показателей object: числа сохраняются числами, ошибки Excel — текстовыми кодами. Дополнительное чтение openpyxl восстанавливает ошибки, которые pandas превращает в NaN. Формулы не пересчитываются; отсутствующий кэш остаётся пропуском, проверка актуальности кэша ещё не реализована.
quantity_provenance и financial_provenance с индексами соответствующих таблиц содержат книгу, лист, номер исходной строки и адреса трёх ячеек показателей. quantity_diagnostics и financial_diagnostics содержат координаты и коды ошибок Excel. branches_provenance и branches_diagnostics оставлены как ссылки на результаты количественной книги. При изменении заголовков, отсутствии филиала или неполном наборе месяцев формирование блокируется с ValueError. Список филиалов и границы таблиц требуют повторной проверки при смене версии книг.

## Для каждого источника зафиксировать
- Роль книги, лист и диапазон.
- Строки заголовков, обязательные и необязательные колонки.
- Тип, единицу и допустимые значения каждого поля.
- Ключ строки и ключи связи между источниками.
- Правила отбора строк: итоги, пустые строки, скрытые области.
- Происхождение записи: файл, лист, исходная строка.

## Срез пациентов для аналога слайда 2
Период подтверждён пользователем: сентябрь, численность на конец 9 месяцев. Суммирование месяцев не применяется. Для текущего примера из quantity_df выбирается строка с происхождением Excel 14 «Количество пациентов», план «Утверждено», факт «Факт по 1С». Одноимённые строки других разделов не объединяются. Используются 18 центров исходного слайда с сопоставлением через предоставленный справочник; дополнительные два филиала DataFrame не добавляются автоматически.

Исполнение — факт/план, отклонение — факт−план; общая сводка рассчитывается по показанным центрам. Пустые/ошибочные значения, нецелая/отрицательная численность и нулевой план блокируют этот экспорт. Статья, колонка факта, общая политика состава центров и представления показателей пока не согласованы для остальных отчётов. Методика, оформление, округление и фактическая проверка описаны в [SLIDE2.md](SLIDE2.md).

## Правила обработки
Не исправлять данные молча. Каждое преобразование имеет правило и проверяемый пример.
Пустое значение, ноль и ошибка ячейки — разные состояния.
Учитывать десятичные разделители, пробелы, проценты, даты и локаль.
Не удалять дубликаты, пока не определён ключ и правило их разрешения.
Для денежных показателей определить точность и момент округления; не полагаться на двоичный float для точных финансовых расчётов.
Для формул определить использование сохранённых значений: openpyxl не пересчитывает Excel-формулы. Отсутствие или устаревание кэша должно иметь согласованную обработку.
Разделять критические ошибки, блокирующие экспорт, и предупреждения, допускающие продолжение.
Сохранять числа как числа до форматирования для слайдов.
