# Архитектура

Уточнение D-040: интерфейс передаёт отдельные позиции и именованные группы с ключами компонентов. `app/engine.py` проверяет уникальность исходных позиций и принадлежность группы одному разделу, вызывает модели notebook для каждого компонента и суммирует проверенные метрики по филиалу. Статистические и расходные страницы создаются независимо от выбора статей; группы 211/212/213 проходят в порядке разделов. На последней странице нечётного раздела используются три показателя. Существующий программный макет notebook создаёт редактируемые диаграммы и встроенные XLSX; входной PPTX остаётся только образцом оформления.

## Приложение Windows — этап GUI от 2026-10-29

Уточнение D-039: каталог выбора формируется из количественной книги; финансовая книга по-прежнему обязательна как источник данных. UI передаёт один список `(код, название количественной статьи)`. Обработчик строит количественные модели по составному ключу, финансовые связывает по коду при единственном финансовом названии или по составному ключу при нескольких. Неоднозначное сопоставление блокирует экспорт. В одном итоговом PPTX находятся обе части для выбранных позиций; отдельные тестовые файлы не создаются.

`app/src` содержит React-интерфейс и тему; `app/src-tauri` — оболочку Tauri 2 и ограниченную команду запуска локального обработчика; `app/engine.py` загружает выбранные книги, вызывает функции расчёта и редактируемых диаграмм из `excel_loading.ipynb`, проверяет пакет и атомарно сохраняет PPTX. При сборке PyInstaller упаковывает Python, notebook, логотип и справочник центров в sidecar. Бюджетные XLSX в приложение не включаются. Интерфейс не содержит формул.

Новый выборочный отчёт размещает до трёх выбранных позиций на слайде. Это отдельный сценарий; исторические 26/130 слайдов notebook сохраняются. Указанные ниже кандидаты PySide6/PyInstaller как единого GUI-стека и ожидание GUI относятся к этапу до нового поручения.

## Текущая самостоятельная генерация (D-019)

Весь рабочий код находится в excel_loading.ipynb. Входы — две книги NL и Excel-справочник центров. quantity_df/financial_df и происхождение формируются один раз; модели получают их аргументами. Рабочий путь не читает презентации NL и прежние результаты. generate_presentation.py — только сообщение о прекращении использования старого шаблонного прототипа; генерации в нём нет.

Проверенные модели → программные слайды → новые пакеты в памяти → проверка всех диаграмм/XLSX → запись двух результатов. Каждый слайд начинается с пустой Presentation(); общая сборка принимает только BytesIO пакетов, созданных в текущем процессе, и отклоняет пути внешних PPTX. Составы центров и стиль заданы явно. Логотип — необязательный ресурс JPG.

Пациенты и процедуры используют общую модель выбора и программный генератор, нагрузка и препараты — отдельные модели/макеты. Числовые правила сохранены. Начиная со слайда 4, источник выбирается по «Код статей» в DataFrame; для нагрузки повторяющиеся коды дополнительно ограничены номером строки Excel. Отображаемое название берётся из «Наименование статей» выбранной книги. Количественные и финансовые препараты используют общий программный макет и отдельные правила входных метрик/пропусков. Квартальный количественный слайд агрегирует месяцы той же модели в отдельные периоды и использует по одной широкой диаграмме на статью или суммарную позицию. Коды пар передаются модели параметром; для тройки Гепарина передаются составные ключи (код, точное наименование). Список дополнительных групп задаёт повторение трёх алгоритмов. Макеты поддерживают два или три независимых блока; существующие парные макеты сохранены. Краевые пробелы кода удаляются только при сопоставлении, исходные таблицы не меняются. Текущий результат — 26 основных и 130 тестовых слайдов. Обе таблицы и их происхождение передаются в сборку аргументами. Холодный запуск не требует output или прежних файлов. Результаты записываются прямо в output. Повторный запуск заменяет два результата без дубликатов; исходные файлы защищены. Старые байты результатов хранятся только для отката, не передаются в построение. Два файла проверяются до записи, временные файлы удаляются; отключение питания между заменами не гарантирует общую транзакцию.

PowerPoint используется только после генерации для локальной проверки готовых результатов. GUI и архитектура будущего приложения ниже остаются предварительным проектом.

## Независимые слои
- UI: выбор файлов, состояния процесса, место для фильтров, диагностика, сохранение.
- Сервис сценария: управляет последовательностью шагов и отменой.
- Импорт: читает книги и сохраняет сведения о происхождении записей.
- Проверка и нормализация: проверяет схему, применяет документированные правила очистки.
- Расчёты: формирует показатели и отчётную модель.
- Фильтрация: преобразует подготовленные данные по согласованным параметрам.
- Экспорт: заполняет шаблон из отчётной модели и сохраняет PPTX.

UI не содержит бизнес-формул. Экспорт не читает Excel непосредственно. Расчёты доступны без запуска графического интерфейса.

## Предлагаемые технологии
- PySide6 для интерфейса.
- openpyxl для чтения XLSX; pandas добавлять только при доказанной потребности.
- python-pptx для работы с PPTX: 1.0.2 проверена в прототипе второго слайда (редактируемая диаграмма и текст); остальные элементы ещё требуют проверки.
- PyInstaller для упаковки Windows EXE.

Это кандидаты, а не утверждённые зависимости. До выбора проверить совместимость с исходными файлами, лицензионные условия распространения и возможности упаковки. Версию Python и зависимости зафиксировать при создании окружения.

## Поток выполнения
Выбор источников → импорт → проверка → нормализация → подготовка → фильтрация → отчётная модель → PPTX.
Точный порядок фильтрации и агрегирования уточняется для каждого показателя: фильтрация после итогового агрегирования не всегда допустима.

Длительные операции выполняются вне потока UI. Повторный запуск блокируется до завершения текущего. Ошибка возвращает приложение в понятное состояние; исходные файлы не меняются.
Финальный файл создаётся через временный результат с заменой после успешной проверки. Перезапись существующего пользовательского результата требует явного выбора в интерфейсе.

## Суммарная позиция расходных материалов — D-033

Выбор исходных статей отделён от сборки отображаемых блоков. Для одиночных позиций результат прежней модели сохраняется. Для группы суммы все четыре компонента сначала проходят ту же проверку полноты месяцев, ключа, происхождения и чисел; затем их план, норма и факт складываются по центру и периоду. Суммарная строка хранит ключи всех компонентов и все исходные индексы. Отклонение и проценты вычисляются после сложения метрик. Слайды получают три обычные модели блоков и используют неизменный трёхблочный макет. Кварталы агрегируют те же компоненты за месяцы выбранного периода.


## Финансовая страница без повторения тройки — D-034
Отдельный финансовый builder использует прежнюю проверку компонентов суммы и парный макет. В общую сборку добавляется только одна страница и пять тестов; список дополнительных троек не расширяется. Проверка слайда принимает отдельный заголовок, чтобы расходы транспорта и питания не назывались лекарственными. Итоговый состав — 25 основных и 125 тестовых слайдов.


## Общая геометрия диаграмм — D-035
Размеры блоков и ручная область построения задаются в notebook; масштаб оси использует компактный запас для числовых подписей. Текст правого итога размещается отдельной фигурой, независимо от оси, при сохранении категории и встроенной таблицы диаграммы. Порядок вычислений и слои данных не меняются. Параметры оформления — PRESENTATION_LAYOUT.md.


## Четыре финансовых квартальных блока — D-036
financial_quarter_model использует существующую проверку финансовых компонентов для каждого квартала, складывает центры и формирует итог девяти месяцев с исходными индексами. Отдельный builder создаёт четыре вертикальные редактируемые диаграммы, общая проверка квартальных слайдов поддерживает этот вариант. Предыдущие builder и формулы сохранены. Состав отчёта расширен до 26/130 слайдов; спецификация SLIDE26.md.
