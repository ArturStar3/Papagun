# Архитектура

## Текущая самостоятельная генерация (D-019)

Весь рабочий код находится в excel_loading.ipynb. Входы — две книги NL и Excel-справочник центров. quantity_df/financial_df и происхождение формируются один раз; модели получают их аргументами. Рабочий путь не читает презентации NL и прежние результаты. generate_presentation.py — только сообщение о прекращении использования старого шаблонного прототипа; генерации в нём нет.

Проверенные модели → программные слайды → новые пакеты в памяти → проверка всех диаграмм/XLSX → запись двух результатов. Каждый слайд начинается с пустой Presentation(); общая сборка принимает только BytesIO пакетов, созданных в текущем процессе, и отклоняет пути внешних PPTX. Составы центров и стиль заданы явно. Логотип — необязательный ресурс JPG.

Пациенты и процедуры используют общую модель выбора и программный генератор, нагрузка и препараты — отдельные модели/макеты. Числовые правила сохранены. Начиная со слайда 4, источник выбирается по «Код статей» в DataFrame; для нагрузки повторяющиеся коды дополнительно ограничены номером строки Excel. Отображаемое название берётся из «Наименование статей» выбранной книги. Количественные и финансовые препараты используют общий программный макет и отдельные правила входных метрик/пропусков. Квартальный количественный слайд агрегирует месяцы той же модели в отдельные периоды и использует две широкие диаграммы. Коды пар передаются модели параметром; список дополнительных пар задаёт повторение трёх алгоритмов. Текущий результат — 18 основных и 90 тестовых слайдов. Обе таблицы и их происхождение передаются в сборку аргументами. Холодный запуск не требует output или прежних файлов. Результаты записываются прямо в output. Повторный запуск заменяет два результата без дубликатов; исходные файлы защищены. Старые байты результатов хранятся только для отката, не передаются в построение. Два файла проверяются до записи, временные файлы удаляются; отключение питания между заменами не гарантирует общую транзакцию.

PowerPoint используется только после генерации для локальной проверки готовых результатов. GUI и архитектура будущего приложения ниже остаются предварительным проектом.

## Независимые слои
- UI: выбор файлов, состояния процесса, место для фильтров, диагностика, сохранение.
- Сервис сценария: управляет последовательностью шагов и отменой.
- Импорт: читает книги и сохраняет сведения о происхождении записей.
- Проверка и нормализация: проверяет схему, применяет документированные правила очистки.
- Расчёты: формирует показатели и отчётную модель.
- Фильтрация: преобразует подготовленные данные по согласованным параметрам.
- Экспорт: заполняет шаблон из отчётной модели и сохраняет PPTX.

UI не содержит бизнес-формул. Экспорт не читает Excel непосредственно. Расчёты доступны без запуска графического интерфейса.

## Предлагаемые технологии
- PySide6 для интерфейса.
- openpyxl для чтения XLSX; pandas добавлять только при доказанной потребности.
- python-pptx для работы с PPTX: 1.0.2 проверена в прототипе второго слайда (редактируемая диаграмма и текст); остальные элементы ещё требуют проверки.
- PyInstaller для упаковки Windows EXE.

Это кандидаты, а не утверждённые зависимости. До выбора проверить совместимость с исходными файлами, лицензионные условия распространения и возможности упаковки. Версию Python и зависимости зафиксировать при создании окружения.

## Поток выполнения
Выбор источников → импорт → проверка → нормализация → подготовка → фильтрация → отчётная модель → PPTX.
Точный порядок фильтрации и агрегирования уточняется для каждого показателя: фильтрация после итогового агрегирования не всегда допустима.

Длительные операции выполняются вне потока UI. Повторный запуск блокируется до завершения текущего. Ошибка возвращает приложение в понятное состояние; исходные файлы не меняются.
Финальный файл создаётся через временный результат с заменой после успешной проверки. Перезапись существующего пользовательского результата требует явного выбора в интерфейсе.
