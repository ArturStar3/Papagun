# Проверки и выпуск

## Текущий запуск проверок
Все проверки этапа подготовки реализованы в `excel_loading.ipynb`: выполните ячейки сверху вниз при `RUN_CHECKS=True` и `GENERATE_PRESENTATIONS=True`. Регрессия использует временный каталог, проверяет ошибки и полный набор; тест количеств создаёт один пятислайдовый PPTX и проверяет данные, геометрию и встроенные XLSX. Внешних проектных скриптов нет.

Необязательная функция `render_presentation` находится в notebook и поддерживает все или выбранные слайды. При `RENDER_PREVIEWS=True` используется установленный PowerPoint, превью показываются из временной папки; проверяются границы текста и высота числовых подписей. По умолчанию просмотр выключен. Перед сохранением очистить outputs. GUI и проверки выпуска ниже относятся к будущему этапу.

## Проверки данных
Использовать небольшие синтетические примеры без реальных финансовых данных.
Проверять правила очистки, связи источников, формулы и граничные случаи: пропуски, нули, дубликаты, неверные типы, ошибки формул.
Для согласованных показателей сохранять входной пример и ожидаемый результат.

## Проверки презентации
Проверять число слайдов, обязательные элементы, значения, единицы, подписи и отсутствие незаполненных маркеров.
Открывать PPTX в целевом приложении и проверять переносы, переполнения, диаграммы и шрифты. Успешное сохранение библиотекой само по себе не подтверждает корректное отображение.
Сравнивать с утверждённым образцом. Не проверять PPTX только побайтовым сравнением.

## Проверки UI
Выбор и отмена выбора файлов, невалидный источник, повторный запуск, длительная обработка, отказ в записи, существующий выходной файл и восстановление после ошибки.
Проверять доступность основного действия, масштабирование и отзывчивость окна.

## Сборка Windows
1. Зафиксировать версию Python и зависимости, выбранный режим PyInstaller и состав ресурсов.
2. Собирать в Windows; убедиться, что тема, шаблоны и нужные библиотеки включены.
3. Проверить запуск EXE без установленного Python.
4. Выполнить полный сценарий на согласованном примере.
5. Проверить русские имена, пробелы в путях, отсутствие прав администратора и запуск из другой рабочей папки.
6. Зафиксировать версию, команды сборки, среду и фактические результаты в docs/STATUS.md.
7. Подготовить инструкцию пользователя: запуск, источники, результат, диагностика.

Режим одного EXE или папки с EXE, подпись и установщик пока не определены. Сам EXE обязателен; установщик не запрошен.

## Правило достаточности
Проверки выбираются по изменению. Для правки документации достаточно проверки файлов и согласованности ссылок. Для бизнес-логики нужны содержательные проверки. Не расширять тестирование без новой причины после прохождения необходимых проверок.
