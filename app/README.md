# Papagun Desktop

Локальное приложение Tauri 2 + React + TypeScript. Обработчик `engine.py` вызывает проверенные функции расчёта и построения редактируемых слайдов из `excel_loading.ipynb`.

## Разработка

Требуются Node.js, Python с пакетами из `requirements-engine.txt`, Rust MSVC toolchain и Visual Studio C++ Build Tools. Скрипт сборки сам находит установленный MSVC toolchain. В корне проекта:

```powershell
python -m pip install -r app/requirements-engine.txt
Set-Location app
npm.cmd ci
npm.cmd exec tauri -- dev
```

В режиме разработки Tauri запускает `python app/engine.py`. Рабочий экспорт собирает слайды в памяти и сохраняет только один выбранный итоговый PPTX. Отдельные тестовые презентации и тестовый скрипт в приложении отсутствуют.

## Сборка Windows

Для упаковки в папке `Исходники` нужна справочная книга соответствия названий центров. Бюджетные книги пользователя в EXE не включаются. Из корня проекта:

```powershell
powershell -ExecutionPolicy Bypass -File app/build-windows.ps1
```

Скрипт упаковывает Python, notebook и справочник в sidecar, затем собирает Tauri NSIS установщик. Настройка `offlineInstaller` включает автономный установщик WebView2; установка и работа готового приложения не требуют сети. Проверенный результат сборки: `app/src-tauri/target/release/bundle/nsis/Papagun_0.1.0_x64-setup.exe` (316,26 MiB). Самостоятельный EXE находится в `app/src-tauri/target/release/papagun.exe`; для запуска рядом с ним нужен `papagun-engine.exe`, поэтому для пользователей предназначен установщик.

Пара книг NL выбирается в интерфейсе. Месяцы и филиалы выбираются плитками: щелчок выбирает один пункт, Shift + щелчок добавляет диапазон, Ctrl + щелчок добавляет или снимает пункт. Недоступные для текущего отчёта плитки отключены. Статьи с первой частью кода меньше 200 не показываются в выборе; оставшийся каталог количественной книги разнесён по четырём разделам. Для лекарств, медицинских изделий и расходных материалов можно выбрать исходные позиции или объединить несколько позиций одного раздела в именованный показатель. Один выбор применяется к обеим книгам: разные названия при одинаковом коде между книгами связываются, а внутри книги позиции одного кода с разными названиями остаются отдельными.

Итоговый PPTX начинается с аппаратов, пациентов и процедур. Эти три слайда создаются без выбора статей: аппараты и пациенты за последний выбранный месяц, процедуры за все выбранные месяцы, каждый для выбранных филиалов. Затем для выбранных статей каждого раздела следуют количественная, финансовая и квартальная страницы: пары показателей, а при нечётном количестве от трёх — последняя тройка. Завершают отчёт две страницы финансовых расходов по транспортным и пищевым статьям. Группы статей сначала проверяются по компонентам и суммируются только в модели отчёта. Исходные XLSX не изменяются. Приложение сохраняет один итоговый PPTX в выбранное место.
